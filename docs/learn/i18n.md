# i18n: app strings in English and Russian

**What:** i18n ("internationalisation") means no user-visible text lives in components. Components ask for a key, and the library returns the text in the current language. We use **i18next** (the engine) and **react-i18next** (the React hooks). **expo-localization** tells us the phone's language.

**Where:** the package `packages/i18n/`.

- `src/locales/en.json`, `ru.json`: every string, in a tree (`home.wordsDue`). Same keys in both files; a test checks it.
- `createI18n(appLanguage)`: makes an i18next instance in one language.
- `useAppLanguage()`: `{ appLanguage, setAppLanguage }` for components (language switch in Settings later).
- `pickAppLanguage(deviceCodes)`: first device language we support, else English.
- `apps/app/app/_layout.tsx` creates the instance, wraps the app in `I18nextProvider` and applies the device language once.

**Use a string:** `const { t } = useTranslation(); t('home.wordsDue', { count: 5 })`. Keys are typed, so a wrong key fails the typecheck.

**Plurals:** Russian has three forms (1 слово, 2 слова, 5 слов), English two. In JSON you write one key per form (`wordsDue_one`, `_few`, `_many`, `_other`) and pass `count`. i18next picks the form with the browser's `Intl.PluralRules`. `plurals.test.ts` covers 1, 2, 5, 11, 21, 22.

**Versions:** i18next 26 and react-i18next 17, not the newest 27 and 18. Those majors were days old when we added them; the previous ones have months of patch releases.

**Gotcha we hit:** the web export is built once, in English. If the first render already used Russian, React reported a hydration mismatch (error 418). So the instance starts in English and the app renders only after the device language is applied.

**Not done yet:** `appLanguage` should default to the user's `nativeLanguage` from the profile (step 3.x); for now it follows the phone. The dev route (`/dev/theme-check`) still has English labels.
